## Possession et isolement

Le runner charge le package externe verrouillé puis appelle directement `chromium.launch({headless:true})`. Il crée exactement **un `browser.newContext()`** vierge pour toute l’exécution. Tous les comptes et onglets de cette exécution utilisent cet objet. Aucun `agent-browser`, `connectOverCDP`, socket artisanal, profil Chrome existant ou snapshot Auth n’est utilisé.

Le profil Chromium temporaire créé par Playwright et le HOME/TMPDIR dédiés appartiennent à cette invocation. Les téléchargements sont dans un répertoire `mkdtemp` privé, supprimé par le nettoyage possédé après vérification ; leurs payloads ne sont jamais copiés dans les preuves. Service Workers bloqués. Routes HTTP(S) et WebSocket filtrées sur les seules origines approuvées `http://127.0.0.1:3159` et `http://127.0.0.1:55431` (équivalents `ws:` pour WebSocket), sans secours distant. Une requête refusée rend la suite en échec.

Un signal pendant `chromium.launch()` oblige le nettoyage à attendre la promesse de lancement avant de fermer le navigateur possédé. Les créations de contexte après interruption sont refusées. Le nettoyage ne peut donc pas se déclarer terminé avant l’arrivée tardive de ce navigateur. Cette précaution de code n’est pas présentée comme un test de signal exécuté.

Les téléchargements sont des blobs locaux produits par l’application ; aucune requête Google réelle n’est ajoutée. La pile et l’application restent gérées par l’orchestrateur existant, avec seul transport Google simulé.

## Préconditions avant navigateur et connexion

Variables requises : `IZORD_LOCAL_WORKDIR`, `LOCAL_STATUS_FILE`, `LOCAL_FIXTURE_FILE`, `IZORD_APP_MANIFEST_FILE`, `IZORD_PLAYWRIGHT_RUNTIME`, `IZORD_ARTIFACTS`, `IZORD_TEST_ACK=IZORD_DISPOSABLE_LOCAL_ONLY`. `PATH` et `DOCKER_HOST` doivent rester explicites selon le banc Colima.

1. Gardes `assertLocalDocker` et `assertLocalTarget`, identité du workdir/réseau existant, statut/fixture/manifeste dans ce même répertoire privé, fichiers réguliers sans lien symbolique et permissions privées, comptes `both`/`b` distincts `@example.invalid`, cohorte intégration complète.
2. Preuve de réutilisation : snapshot fictif conservé, workdir/runId concordants et contact témoin connu dans le payload local. Aucun reset, création de compte ou migration par le runner.
3. Comparaison SHA-256 des 13 fichiers pertinents entre dépôt et copie servie, et des empreintes du manifeste lorsqu’elles sont présentes. Le manifeste peut être `ready` ou `stopped` : ce statut décrit la dernière observation, pas la disponibilité courante.
4. Sondes HTTP réelles, sans redirection, bornées à deux secondes : application `/api/drive/diagnostic` attendue 401 et Auth local `/auth/v1/health` attendu 200. Un refus intervient **avant l’import Playwright, la création du profil et toute connexion**.
5. Package Playwright stable épinglé, package installé/lock cohérents, bundle officiel `chromium-headless-shell` correspondant à `browsers.json` dans `<runtime>/browsers`. Pas d’installation ni de fallback automatique.

L’interface des gardes pures est documentée en tête de `cache-playwright-target.mjs` pour être testée sans navigateur. `isAllowedCacheBrowserURL(value,{webSocket=false})` retourne un booléen ; `assertCachePlaywrightInputs(...)` retourne les cibles validées ou une erreur à code `CACHE_*` sans valeur sensible.

## Diagnostics et protocole

Chaque invocation écrit `cache-playwright-trace.jsonl` et `cache-playwright-result.json` dans un dossier neuf. Refus d’écraser une tentative précédente. Horodatages absolus et relatifs : action/groupe courant, début/fin/échec, téléchargement, fermeture/crash de page, déconnexion navigateur, début/fin de chaque fermeture volontaire, nettoyage et terminaison du processus propriétaire. Le résultat est écrit **après le nettoyage**, et un événement JSONL `owner-process-exit` consigne le code réellement observé à la sortie.

`DEBUG=pw:browser` est activé dans le seul runner et son stderr intercepté avant import. Les messages techniques expurgés et leur empreinte sont conservés pour permettre le diagnostic du premier échec ; les motifs structurés du logger peuvent fournir PID, code de sortie et signal Chromium. Sinon la valeur reste **« non disponible »**. Les secrets connus du statut/fixture, JWT, valeurs d’en-têtes Auth/cookies, URLs avec query strings et lignes d’arguments de saisie/évaluation sont retirés avant publication. Aucun message brut, HAR, vidéo, trace Playwright ou fichier de session. Une fermeture/crash/dialogue inattendu interrompt la suite ; le nettoyage ne la transforme pas en succès. L’orchestration principale doit contrôler les artefacts avant partage.

Le runner n’effectue aucune relance complète : `retries: 0`. L’orchestration principale doit prévoir trois invocations séquentielles avec nouveaux dossiers/contexte/profil, et **arrêter les suivantes au premier échec inexpliqué**, conformément au nouveau prompt. Aucun autre navigateur parallèle. Les délais demeurent 15 secondes pour états/actions, 20 secondes pour lancement et deux secondes pour sondes ; pas de hausse arbitraire du timeout historique.

Même trois futurs résultats verts ne démontreraient pas la cause du premier timeout historique ni de la fermeture du troisième ancien essai. Ces deux incidents restent séparés du résultat de ce nouveau pilote.
