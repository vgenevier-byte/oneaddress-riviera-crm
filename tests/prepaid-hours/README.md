# Vérification des forfaits prépayés

Les essais utilisent une pile Supabase dédiée, avec PostgreSQL, Auth et PostgREST réels, uniquement sur `127.0.0.1` (API `56031`, base `56032`, courrier `56034`, application `3197`). Les utilisateurs et données sont fictifs. Aucun fichier `.env` du dépôt n'est lu. Les clés, mots de passe et sessions restent dans les fichiers temporaires privés de la pile ; ils ne figurent pas dans les rapports.

1. Lancer `server-stack.mjs` avec `IZORD_TEST_ACK=IZORD_DISPOSABLE_LOCAL_ONLY`, `DOCKER_HOST=unix://$HOME/.colima/default/docker.sock` et `SUPABASE_BIN` pointant vers le CLI installé. La sortie donne le dossier temporaire et les commandes d'arrêt de cette seule pile.
2. Définir `PREPAID_HOURS_STATUS_FILE` sur son fichier `local-status.json`, puis exécuter `server-prepare.mjs` sur cette pile fraîche.
3. Exécuter `server-apply.mjs` pour installer la migration, puis `server-tests.mjs` pour les parcours Auth/RPC. Les réexécutions de développement se font après `server-reset.mjs`, qui ne touche que les sources fictives et tables de cette fonctionnalité dans la pile dédiée.
4. `server-admin-reconciliation.mjs` vérifie séparément la reprise administrative avec un autre intervenant fictif. Cette opération déclare explicitement son canal administratif ; elle n'invente aucune session Auth. Elle contrôle le refus d'un instantané devenu obsolète, le rejeu idempotent, la sauvegarde et le journal persistants.
5. Pour les captures, utiliser `server-reset.mjs`, puis `server-demo.mjs first` : 500 € payés, 32 h réalisées et 2 h à couvrir. Après la première capture, `server-demo.mjs renew` produit 1 000 € payés et 28 h disponibles. Le formulaire de l'application permet le même renouvellement avec confirmation explicite du paiement fictif.

Le rapport `docs/prepaid-hours/server-results.json` décrit les 13 scénarios Auth/RPC validés : achats et consommation exacts, renouvellements concurrents et rejoués, paiement existant réservé, filtres, 120 quarts d'heure, franchissement entre forfaits et corrections, frais et facture liée, nouvelle authentification, tarif horaire inchangé, exports et droits restreints/révoqués. Deux régressions finales sont vérifiées séparément par `server-edge-regressions.mjs` et `docs/prepaid-hours/edge-regressions-results.json` : suppression autorisée d'un intervenant horaire sans historique, et masquage de la référence facture dans les exports lorsque seul son droit de lecture est accordé. `docs/prepaid-hours/admin-reconciliation-results.json` rapporte le test de reprise administrative. Ces preuves concernent exclusivement les données fictives locales.

Le rapprochement réel de Troy est documenté séparément dans `docs/prepaid-hours/troy-reconciliation.md` et son JSON. Son état de reprise doit être confirmé par un contrôle Production distinct.

Pour le navigateur, lancer `serve.mjs` avec `PREPAID_HOURS_TEST_ACK=PREPAID_HOURS_LOCAL_ONLY`, puis `browser.mjs` avec le même fichier de pile et `IZORD_TEST_ACK=IZORD_DISPOSABLE_LOCAL_ONLY`. La compilation et le navigateur bloquent les requêtes hors boucle locale. Le test renouvelle explicitement le forfait fictif ; les captures se trouvent dans `docs/prepaid-hours/captures`.
